## tRPC 迁移 Phase 5：去掉 frontend/api.ts 的 trpc 封装，前端直接调用 tRPC

背景：`frontend/api.ts` 原有一批「纯透传」封装（getSchemas/getTables/executeDdl/getAiConfig…），内部就是 `trpc.db.xxx.query/mutate`。按用户要求改为组件直接调用 tRPC。

决策（用户确认）：
- 范围：只去掉纯透传封装；保留带副作用的会话/宿主函数（connectPostgres、disconnectPostgres、prefetchDbCapabilities/DataTypes、disconnectPostgresOnPageUnload、subscribeEvents、subscribeServerMessages、subscribeAccountState、saveFileViaVscode、readFileViaVscode、setAiKeyViaVscode、deleteAiKeyViaVscode、assertFeatureSubscription），并在 api.ts 导出 `dbConn(connectionId)` 作为 db 入参构造器。
- dbType：保留必填（组件调用形如 `trpc.db.schemas.query(dbConn(id))`）。后端 api-core 中 dbType 对非 connect 的 db/* 实为提示、assertSessionDbType 是空实现，但按用户选择不改后端 schema。

改动：
- 返回类型下沉到后端 router（此前 handleApiRequest 返回 unknown）：`backend/trpc/router/db.ts`（DbResults 映射 + call 泛型）、`ai.ts`、`subscription.ts`、`query-history.ts` 补类型；`connections.ts` 的 list/save/delete/updateMeta/reorder 也补类型。导出 `PartitionInfo`/`SessionMonitorResult`/`InstalledExtensionsResult` 供前端类型引用。
- 重写 `frontend/api.ts` 为「会话/宿主」模块（412 行 → 约 170 行）。
- 用一次性 codemod 批量改写 20 个前端文件的调用点与 import（脚本已删）。注意：codemod 需处理「保留函数 + db 调用」共存时补 `dbConn` 导入，以及 `ReturnType<typeof fn>` 类型引用（extensions-modal / partition-table-modal / pg-stat-modal 改为引用后端导出类型）。

验证：tsc 后端 trpc 目录零错误；前端仅剩既有问题（CSSProperties 驼峰、bun:test、electrobun、table-designer-shared 等）。启动 server-node 冒烟：connections.list→array(1)、ai.configGet→ok、subscription.account→ok、queryHistory.search→array(314)、db.schemas(无会话)→预期报错。

任务列表校正：Phase 3/4/6 标记完成，Phase 5 完成；剩 Phase 7（VSCode 适配）、Phase 8（清理旧 transport/SSE）。

## 约定
- 组件调用 db/* 一律 `trpc.db.xxx.query/mutate({ ...dbConn(connectionId), ... })`；不再新增 api.ts 封装。
- 返回类型真源在后端 router，不在前端。

## tRPC 迁移 Phase 7：VSCode 扩展改用 TypeFox vscode-messenger 作为纯传输层

用户要求：Phase 7 要建一个**自定义 tRPC link**，用 typefox 的 `vscode-messenger` 实现；messenger 的 method 与 tRPC 方法无关，所有数据放 params，它只做传输层（免手写请求配对）。

新增：
- `shared/src/vscode-messenger-rpc.ts`：协议常量/类型。统一 `RPC_CALL`（params 判别联合 `{kind:'trpc', path, type, input} | {kind:'host', method, input}`）；订阅 `SUBSCRIBE`(request) + `UNSUBSCRIBE`/`SUBSCRIBE_DATA`/`SUBSCRIBE_ERROR`/`SUBSCRIBE_COMPLETE`(notification)；宿主推送 `HOST_ACCOUNT_STATE`；`HOST_METHODS`（openSubscriptionLogin / logoutSubscription）。仅 type-only 依赖 vscode-messenger-common，无运行时依赖。
- `frontend/transport/vscode-messenger.ts`：webview Messenger 单例 + `getVsCodeWebviewApi()`/`isVsCodeWebview()` + `requestSubscriptionLogin/Logout()`。
- `frontend/transport/trpc-vscode-link.ts`：`createVscodeMessengerLink()` → `TRPCLink<AppRouter>`。query/mutation 走 `RPC_CALL` 一次往返；subscription 用 `sendExtensionRequest(SUBSCRIBE)` 建立，数据按 `op.id` 多路复用通知回流，teardown 发 `UNSUBSCRIBE`。
- `frontend/transport/vscode-messenger-transport.ts`：`VsCodeMessengerTransport implements IApiTransport`，仅承载宿主能力（`vscode/*`）与账号推送。
- `backend/vscode-messenger-bridge.ts`：`createWebviewRpcBridge({messenger, receiver, getContext, procedureOverrides, hostCall})`。用 `appRouter.createCaller()` 分发；handler 用 `{sender: receiver}` 作用域注册（**否则第二个面板会抛 "already registered"**）；订阅兼容 observable（legacy）与 asyncIterable；错误用普通对象 `{message, data}` 抛出（Error 实例会被 messenger 把 data 换成 stack，丢失 subscriptionRequired）。

接线与删除：
- `frontend/index-webview.tsx`：`setTransport(new VsCodeMessengerTransport())` + `setTrpcTransportLink(createVscodeMessengerLink())`。
- `vscode-extension/src/extension.ts`：`new Messenger()` + `messenger.registerWebviewPanel(panel)`；巨型 `onDidReceiveMessage` switch 改为 `hostCall` 分发（save-file/read-file/clipboard/ai-key/登录/退出）；`procedureOverrides` 处理 `subscription.assert`（扩展侧凭据 + feature 校验）与 `subscription.account`（SecretStorage）；账号改用 `HOST_ACCOUNT_STATE` 通知推送。
- `frontend/sidebar.tsx`、`frontend/subscription/portal.ts`：改用 `isVsCodeWebview()` + `requestSubscriptionLogout/Login()`。
- **删除** `frontend/transport/vscode-transport.ts`、`backend/api-handlers-vscode.ts`（手写 pending/messageId 配对）。
- 根 `package.json` 补 `vscode-messenger`、`vscode-messenger-webview`（^0.7.0），并 `bun install` 写入 bun.lock。

验证：extension tsconfig 与前端相关文件 tsc 零新增错误；`bun vscode-extension/build.ts` 通过（前端/extension 双包均含 `dbplayer/rpc`，`vscode` 仍为 external）；webview 产物未混入后端服务代码。

关键依赖行为（已核对 node_modules 源码）：webview `processResponseMessage` 以 `msg.error`（普通对象 `{message,data}`）reject；tRPC 客户端对 `result.type==='data'` 走 onData；`equalParticipants`/`sendersOverlap` 按 webviewId 比较，支持多面板。

## 约定（Phase 7 补充）
- VSCode 通道只有一套协议：messenger 的 `dbplayer/rpc` + 订阅通知；新增宿主能力只需在 extension 的 `hostCall` switch 加分支，不再手写 messageId 配对。
- 宿主专属 tRPC procedure 用 bridge 的 `procedureOverrides` 覆盖，不改 router。

## tRPC 迁移 Phase 8：彻底消除 transport，宿主能力也走 tRPC（推翻 Phase 7 的 host 通道）

用户明确两点：
1. 目标不是「保留 transport 只接过去」，而是**消除 transport，完全用 tRPC 替代**——Phase 7 的 `vscode-messenger-transport.ts` / `IApiTransport` 属于遗留，应删。
2. 业务层的 `dbplayer` 订阅登录**不要在 messenger 里单独定义 method**；作为 tRPC procedure 交给 extension host 按 path 处理。

### 最终形态（单一调用面 = tRPC）
- `appRouter` 新增 `host` router（`backend/trpc/router/host.ts`）：`saveFile/readFile/clipboardWrite/clipboardRead/aiKeySet/aiKeyDelete`，服务端默认抛 `TRPCError({code:'METHOD_NOT_SUPPORTED'})`。浏览器/Standalone 落到「不支持」→ 调用方回退浏览器下载 / 原生 file input（语义与旧的「抛错即回退」一致）。
- `subscription` router 新增 `openLogin` / `logout`（服务端 unsupported，宿主覆盖）与 `onAccountState`（服务端 no-op observable，永不触发）。
- `shared/src/vscode-messenger-rpc.ts` 只剩**纯传输契约**：`RPC_CALL{path,type,input}` + `SUBSCRIBE{opId,path,input}` + `UNSUBSCRIBE`/`SUBSCRIBE_DATA|ERROR|COMPLETE`。删除 `HOST_METHODS`、`HostCallPayload`、`HOST_ACCOUNT_STATE`、`kind:'host'`。
- `backend/vscode-messenger-bridge.ts`：删 `hostCall` 与 `kind` 分流；统一 `invokeProcedure(path, input)`（**override 优先，其次 appRouter**），`procedureOverrides` 同时作用于 query/mutation 与 subscription。
- `vscode-extension/src/extension.ts`：`createHostCallHandler` → `createProcedureOverrides(context, deps)`，按 path 覆盖 `host.*`、`subscription.openLogin|logout|onAccountState`；账号态改为模块级 `accountStateListeners` + `notifyAccountState/pushAccountState`，由 `onAccountState` override 转成 observable（订阅建立即推一次当前状态）。
- 前端：`frontend/platform.ts`（`isVsCodeWebview`/`isElectrobun`/`getVsCodeWebviewApi`，原 `frontend/transport/vscode-messenger.ts` 的探测逻辑迁入）；`frontend/vscode-messenger.ts`（Messenger 单例）；`frontend/trpc-vscode-link.ts`（link，params 去掉 `kind`）。
- 调用点**直接调 tRPC**（不再经 api.ts 封装）：`trpc.host.saveFile/readFile/clipboardRead/aiKeySet/aiKeyDelete`、`trpc.subscription.openLogin/logout/onAccountState`。`api.ts` 仅剩会话生命周期（dbConn/connect/disconnect/prefetch/subscribeEvents/assertFeatureSubscription/disconnectOnPageUnload）。

### 删除
`frontend/transport/`（整个目录：index.ts、http-transport.ts、vscode-messenger-transport.ts）、`frontend/host-bridge.ts`、`shared/src/transport.ts`（→ 改名 `shared/src/api-methods.ts`，只留业务 `ApiMethod`/`ApiRequestPayload`，去掉 `vscode/*`、`IApiTransport`、`TransportOnSubscribe`、`API_METHODS` 中的 vscode 项、`ServerPushMessage`（types.ts）、`parseAccessTokenQuery`）。
`shared/src/transport.ts` 改名 `api-methods.ts` 后 `shared/src/index.ts` 同步改导出。
`standalone/server-bun.ts` 顺带补上 tRPC handler（原来只有旧路由，是缺口）。

### 后端 HTTP 面收敛
`backend/api-handlers-http.ts` 只保留 `POST /api/db/disconnect`（页面卸载 keepalive，tRPC 批量协议无法表达）；删除 `createApiRoutes`/`handleApiPost`/`HTTP_API_METHOD_SET` 用法、SSE `/api/events`、`/api/hello`。`server-node.ts` 只挂 `/api/trpc/*` + dbplayer 订阅路由 + disconnect；`server-bun.ts` 同构。
